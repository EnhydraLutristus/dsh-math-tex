# docs/ — 这三份文档的分工

这里放的是**判据的来源**，不是现状。现状、安装步骤、测试清单在仓库根的 `STATUS.md`。

| 文档 | 什么时候写的 | 回答什么问题 |
| --- | --- | --- |
| `FINDINGS.md` | 侦察阶段，实现之前 | **到底坏在哪**：为什么红字不是崩溃、判据为什么不能只看异常、修复函数能做什么 |
| `KATEX-MEASUREMENTS.md` | 同上，与 FINDINGS 同期 | **数字**：31 个用例逐个过两段渲染链的实测结果，各档阈值与内存/耗时曲线 |
| `DESIGN.md` | 侦察阶段，实现之前 | **方案怎么定的**：风险模型、三层防御、被否掉的方案与原因、已核实/未核实的诚实清单 |

## 为什么保留

后面每一处实现都能追溯到这里的某条结论或某个数字，例如：

- 判据是"严格通过**且**输出无 `#cc0000`"，而不是"有没有抛异常"——`FINDINGS.md` §0 与
  `KATEX-MEASUREMENTS.md` 的 `\htmlClass{red}{x}` 用例；
- 只做两种定点替换、其余降级为源码围栏——`FINDINGS.md` §4 的原理验证；
- 拦截点必须是 `llm/stream`——`FINDINGS.md` §6。

如果哪天要改判据，先改这里的结论（重跑脚本），再改代码；顺序反过来就会出现
"测试全绿但依据是错的"。

## 两点说明

- 当时的包名叫 `math-guard`（原型，已退役），现在是 `dsh-math-tex`。文档里的包名、
  路径、文件名保持原样，不做追溯性改写。
- 文中提到的复现脚本（`katex-stress.js`、`katex-personas.js`、`repair-math.js`、
  `list-asar.js`、`math-risk.probe*.js` 等）是侦察期放在仓库外的临时脚本，没有随包发布；
  它们的结论已经写进文档，需要重跑时按文中的命令与用例重建。
